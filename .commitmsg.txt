Fix horizontal overflow / white-space bleed on mobile Safari

The site was leaking horizontal scroll on iOS Safari at small viewports
(visible as a strip of white space along the side of the page when
zoomed out, and a "bounce" past the left edge on rubber-band scroll).
Three causes, all fixed:

1. No overflow-x clipping on the root element. Any rogue child a single
   pixel too wide would push the body wider than the viewport.
   - Set `overflow-x: hidden; overflow-x: clip;` on both `html` and
     `body`. The `clip` value is preferred (doesn't break ancestors of
     `position: sticky`); `hidden` is the fallback for older WebKit.
   - Added `width: 100%; max-width: 100vw;` on body — older iOS Safari
     ignores overflow-x on body without an explicit width constraint.

2. Negative margins escaping containers on the mobile category-chip
   filter (`-mx-1` in ShopFiltersBar) and the FrequentlyBoughtTogether
   horizontal scroller (`-mx-2`). Removed both — the existing parent
   padding already produces the visual gutter we wanted.

3. Long UUID order IDs in `font-mono` on /track-order and
   /order-confirmation could push the content wider than narrow
   viewports. Added `break-all` so they wrap.

Also added an explicit `viewport` export in `app/layout.tsx`:
- `width: device-width, initialScale: 1` (canonical mobile viewport)
- `viewportFit: 'cover'` so safe-area insets work correctly on iPhones
  with notches / Dynamic Island.
- `themeColor: #ffffff` so the Safari URL bar matches the page background.

Tested via production build (27 routes, 0 TS/lint errors).
