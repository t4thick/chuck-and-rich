fix(checkout): remove Stripe demo-key fallback so payment can't silently hang

- lib/stripe-browser.ts: return null instead of falling back to Stripe's
  universal demo pk_test_TYoo... key (it belongs to a different account
  than the user's STRIPE_SECRET_KEY, which causes confirmPayment to hang).
- CheckoutStripePayment: show a clear "Payments are not configured" message
  when NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY is missing instead of mounting
  Elements with a mismatched key.
- /api/checkout/payment-intent: also validate the publishable key is set
  and that it shares an account ID with the secret key; return 503 with
  a precise error message when they mismatch.
